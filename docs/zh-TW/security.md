# 資安說明與威脅模型

## 1. 這個工具會碰到什麼

`sitk` 以管理權限連到全校網路設備。因此要同時防兩件事：**洩漏學校資訊**，以及**工具（或 AI）把網路改壞**。

## 2. 不能外流的資料（請放在 site/，不要提交、不要貼給雲端 AI）

| 類別 | 例子 |
| :--- | :--- |
| 憑證 | 密碼、API token、SSH 私鑰、SNMP community、Wi-Fi PSK、憑證檔 |
| 拓撲 | 網段、VLAN、閘道、防火牆規則、NAT、開放埠 |
| 台帳 | 主機名、MAC、序號、型號、韌體版本、IP 與教室對應 |
| 弱點 | 「某設備還是預設密碼」「某服務沒修補」這類紀錄 |
| 個資 | 教職員生姓名、帳號、班級、Wi-Fi 終端軌跡 |
| 身分線索 | 校名、網域、截圖、檔案 metadata |

分享經驗給其他學校時，請只分享**方法**：把 IP 改成文件專用網段（`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`），網域改成 `example`，人名改成角色。

## 3. 工具內建的防護

| 防護 | 做法 |
| :--- | :--- |
| 預設唯讀 | 變更類動作沒有 `--apply` 時只回 `DRY_RUN` |
| 高風險確認 | `policy.confirm_required` 中的領域還需要 `--confirm <目標名稱>` |
| 網段範圍 | 只對 `scope.allowed_networks` 內的位址動作；範圍為空則拒絕啟動 |
| 白名單 | 台帳外的名稱一律 `UNKNOWN_ASSET` |
| 生命週期 | 非 ACTIVE 設備不得變更，查詢結果標示 `NOT_ACTIVE` |
| 死人開關 | 防火牆套用後以新連線探測，失敗則計時器自動回滾 |
| 憑證隔離 | Keychain / 0600 檔；`Secret` 型別遮蔽 repr；密碼不出現在命令列（`sshpass -e` 經環境變數） |
| 注入防護 | DNS/DHCP 搜尋字串限定安全字元並以固定字串比對；遠端欄位標示 `untrusted` |
| 稽核 | 所有 `--apply` 寫入 `logs/audit.jsonl`（0600），密碼欄位自動遮蔽 |
| 不用預設密碼 | 找不到憑證就拒絕執行；Grandstream 偵測到出廠密碼會提醒 |

## 4. 給導入學校的建議

1. **最小權限**：巡檢用唯讀帳號；變更帳號分開，平時不放在工具裡。
2. **管理網段隔離**：設備管理介面不要讓學生／訪客網段連得到。
3. **換掉出廠密碼**：工具與文件不會幫你記任何預設密碼。
4. **本地模型優先**：若用雲端模型，不要讓它讀台帳、設定備份或日誌。
5. **使用者貼出的密碼視為已外洩**：請立即更換。
6. **定期檢查稽核日誌**，確認沒有非預期的變更。
7. **法規**：學校屬資通安全管理法適用對象，教職員生資料受個資法保護；導入前請依所屬教育主管機關的資安規範辦理，並取得校內權責主管同意（本文件不構成法律意見）。

## 5. 專案自身的供應鏈防護

- 只用 Python 標準庫，沒有第三方相依套件。
- CI 對每個 PR 執行測試與秘密掃描（gitleaks）。
- 第三方 GitHub Action 以 commit SHA 釘版；工作流程預設唯讀權限。
- 修改轉接器的寫入路徑或任何守門檢查的 PR，需維護者親自審核。
- 弱點回報方式見 [SECURITY.md](../../SECURITY.md)。
