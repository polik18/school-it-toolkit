# 建議建立的可管理資源

> 想讓校園網路「查得到、修得動、交得了接」，甚至讓 AI 幫忙維運，關鍵不在買什麼設備，而在先把下面這些**管理基礎**建立起來。依投入成本由低到高排列，可以逐項導入。

## 1. 一份可信的台帳（最重要、成本最低）

- **一台設備一行**：名稱、類型、管理 IP、MAC、型號、所在空間、生命週期狀態（ACTIVE / STAGING / RETIRED / SPARE）。
- **空間表**：班級、專科教室、辦公室，並記下老師平常的叫法當別名（例如「306班」「三年六班」）。台帳有了別名，AI 才不用猜。
- **命名規則**：用「類型-空間-序號」（例如 `sw-a3-01`、`ap-a306`、`pc-a306`），看名稱就知道是什麼、在哪裡。
- **生命週期要誠實**：現場調試中的設備標 STAGING，避免拿調試中的資料當線上現況判斷。
- 學期初、設備調撥後一定要校正一次台帳。

## 2. 管理網段與可達性

- **獨立管理網段**：交換器、AP 控制器、防火牆、伺服器的管理介面放在獨立網段，學生與訪客網段連不到。
- **管理電腦固定在管理網段**，並能連到所有設備的管理介面。
- 交換器開啟 **LLDP**，日後才能自動畫出拓撲、找出上下聯關係。
- 端點電腦開啟 **Wake-on-LAN**，跨網段喚醒時規劃好廣播位址或轉送。

## 3. 帳號、金鑰與憑證

- **統一的管理帳號**（每類設備一個），不要用個人帳號管理設備。
- **SSH 金鑰優先、密碼次之**；金鑰只放在管理電腦，私鑰永不複製到其他地方。
- **唯讀巡檢帳號與變更帳號分開**；有 REST API 的設備（例如無線控制器）建立最小權限的 API 帳號。
- **集中保存憑證**：macOS Keychain、密碼管理器，或權限 0600 的檔案；不寫在腳本、文件或聊天內容裡。
- **全面換掉出廠預設密碼**，並定期檢查是否還有設備可以用預設密碼登入。

## 4. 可回復的變更習慣

- **先唯讀、後變更**；任何變更先產生預覽，確認後才執行。
- 防火牆等可能讓自己斷線的變更，使用**死人開關**（套用後若管理通道斷了，自動回滾）。
- 變更前**自動備份組態**；備份屬敏感資料，只存在管理端。
- **稽核日誌**：誰、何時、對哪台設備、做了什麼、結果如何。

## 5. 長任務與停電流程

- 批次維護（全校電腦更新、話機重開）用**可中斷續跑的清單**，每台都要實測確認才算完成。
- 事先寫好**停電關機與復電驗收的順序**：網路 → 儲存 → 伺服器 → 端點；前一階段沒通過不跑下一階段。
- 人工步驟（例如登入儲存設備確認磁碟陣列）明確寫進流程，完成後才勾選。

## 6. 本地 AI 推論伺服器（選配）

如果想用 AI 協助維運，又不希望校內資料上雲，可以考慮在校內架一台本地推論服務：

- **硬體**：記憶體愈大可跑的模型愈大；統一記憶體較大的 Apple Silicon 電腦，或有獨立顯示卡的 PC 都可以。
- **軟體**：任何提供 **OpenAI 相容 API** 的本地推理服務（例如 Ollama、LM Studio、oMLX）。
- **模型選擇**：維運任務以「穩定呼叫工具、照格式輸出」為優先，不一定要最大的模型；混合專家（MoE）模型在一般硬體上常有不錯的速度。
- **安全**：推理服務只開放給管理網段、啟用 API 金鑰；金鑰同樣存在憑證庫。
- **搭配本工具**：小模型容易拼錯指令或自己編名稱，所以讓它只透過 `sitk` 的固定指令與 JSON 結果工作，安全檢查交給程式。
- 詳細架設方式見 [local-ai-workstation.md](local-ai-workstation.md)。

## 7. 交給 AI 之前的檢查表

- [ ] 台帳完整，別名涵蓋老師常用的叫法
- [ ] 管理網段範圍已寫進 `site.toml`
- [ ] 憑證都在憑證庫，`sitk doctor` 沒有缺少項目
- [ ] 巡檢用唯讀帳號
- [ ] 高風險領域已列入 `policy.confirm_required`
- [ ] 已在示範站點演練過，知道每種 `status` 該怎麼處理
- [ ] 稽核日誌位置已知，會定期查看

> 分享經驗給其他學校時，也請只分享**方法**：不要公開自己學校的設備型號組合、數量、網段、帳號或尚未修補的弱點。
